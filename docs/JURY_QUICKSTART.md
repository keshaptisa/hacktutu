# Быстрый старт

- Название команды: `моя дикая кассандра`
- Караханов Максим
- Недозорова Алиса

## Что это

Этот документ нужен для быстрой проверки проекта без погружения в код.

Он помогает за 2-3 минуты:

- запустить сервис;
- пройти основной пользовательский сценарий;
- увидеть ценность продукта;
- проверить, что интерфейс и ключевые сценарии работают.

## Как запустить

1. Установить зависимости:
   `pip install -r requirements.txt`
2. При необходимости создать `.env` на основе `.env.example`
3. Запустить приложение:
   `uvicorn app.main:app --reload`
4. Открыть в браузере:
   `http://127.0.0.1:8000`

## Что проверить в первую очередь

### 1. Главный сценарий

На главной странице:

- выберите бюджет;
- выберите длительность;
- отметьте 2-3 настроения;
- при желании уточните город отправления и пожелание;
- нажмите `ПОГНАЛИ`.

Ожидаемый результат:

- появляется экран сборки поездки;
- затем отображаются три разных сценария.

### 2. Просмотр сценария

Нажмите `ПОСМОТРЕТЬ` у любого варианта.

Ожидаемый результат:

- открывается детальный экран;
- видны бюджет, длительность, транспорт, объяснение выбора и план поездки.

### 3. Доработка сценария

В блоке `Что можно улучшить` введите, например:

`Хочу дневной поезд и отель ближе к центру`

Нажмите `ДОПИЛИТЬ МАРШРУТ`.

Ожидаемый результат:

- маршрут пересобирается;
- пользователь видит, что именно изменилось.

### 4. Переход к покупке

Нажмите `КУПИТЬ ПОЕЗДКУ`.

Ожидаемый результат:

- открывается корзина;
- в корзине показаны доступные ссылки на оформление;
- если часть данных недоступна, это честно отражено в интерфейсе.

## Что важно заметить при оценке

- проект решает реальную travel-задачу, а не просто демонстрирует MCP;
- пользователь не собирает поездку вручную, а получает готовые сценарии;
- сценарий можно доработать без полного перезапуска поиска;
- интерфейс ориентирован на быстрое принятие решения;
- при нестабильности источника данных продукт не падает в пустой экран.

## Если живые данные недоступны

Проект поддерживает деградированный режим. Это значит, что при проблемах с источником данных продукт старается показать запасной сценарий вместо фатальной ошибки.
